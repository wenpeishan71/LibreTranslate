# 术语库格式与建设机制

## 文件格式

`terminology_zh_ru.csv`，UTF-8 编码，表头固定为：

| 列名 | 含义 | 说明 |
|---|---|---|
| `zh` | 中文原文 | 术语预检时按此列匹配 |
| `ru` | 俄语译法 | 翻译后回填的目标文本 |
| `category` | 分类 | 课程术语 / 教务用语 / 机构名称 / 缩写 / 课程编号 / 人名 |
| `note` | 备注 | 可留空；标注易错点、使用限制 |

## 匹配规则（与 `glossary_precheck.py` 保持一致）

1. **最长优先匹配**：同一句话同时出现"概率论与数理统计"和"概率论"时，按更长的术语处理；
2. **缩写与课程编号不翻译**：`category` 为 `缩写` 或 `课程编号` 的条目，在翻译前后保持原样；
3. **人名规则**（已落地，见 `name_translit.py` 与 `names_zh_ru.csv`）：
   已登记人名取人工定译 → 未登记但用字在迷你拼音表内则按规则转写 → 其余标记"待人工核对"；
   俄语教师姓名（西里尔字母）一律保留原文。人名不进术语库，单独用 `names_zh_ru.csv` 维护；
4. **冲突处理**：同一 `zh` 对应多条 `ru` 时，`note` 中必须标注使用场景，由社团校对后择一。

## 建设机制（可持续积累）

```
师生发现翻错 → 提交条目（表单/PR） → 社团术语小组每周校对 → 合入 CSV → 下次翻译自动生效
```

- 校对标准：以学校教务处、院系官网的双语材料为准，无官方译法时由中俄双语教师确认；
- 每条入库术语需记录提交人与校对日期（后续在 CSV 增加 `reviewed_by`、`reviewed_at` 列）。

## 与商业翻译服务的对比

商业翻译 API 是黑盒：术语错了没法改、改了下次还会错、数据要发到第三方。
校园术语库的每一个词条都可以追溯、校对、修正——**术语库本身就是这份工作留下的资产**。

## 可推广性

任何中外合办院校（中英、中俄、中日……）只需替换 `ru` 列为目标语言、
按本校课程体系重新填表，即可复用同一套流程与脚本。
